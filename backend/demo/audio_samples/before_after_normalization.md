# TTS script-normalization: before / after

The demo checklist asks for a before/after **audio** sample. Producing the actual
`.wav` pair needs a live TTS key (Sarvam Bulbul or ElevenLabs), which isn't available
in this environment -- see DECISIONS.md's known-limitations section. This is the
before/after **text** that would be fed to TTS, generated by
`roxroom.bots.text_normalizer.normalize_for_tts` (see `tests/unit/test_text_normalizer.py`
for the automated version of this same check).

Once a key is available: synthesize both `before` and `after` strings below with the
same voice and drop the resulting `.wav` files in this folder as
`before_normalization.wav` / `after_normalization.wav`. Expect `before` to mispronounce
"kya"/"accha"/"batao"/etc. with English letter-phonetics; `after` should pronounce them
correctly since they're already in Devanagari.

## Sample 1

- **before** (raw Romanized Hinglish, what a naive prompt might produce):
  `haan bilkul, mujhe yeh samjhao ki technology kaise kaam karti hai`
- **after** (`normalize_for_tts` output, what actually gets sent to TTS):
  `हाँ बिल्कुल, मुझे यह समझाओ कि technology कैसे काम करती है`

## Sample 2

- **before**: `AI Dost, 5G kya hota hai?`
- **after**: `ए आई Dost, फाइव जी क्या hota hai?`

  (`hota` isn't in the safety-net lexicon -- a real reply would come from the LLM
  already in Devanagari per the persona system prompt; this sample shows only the
  fallback layer in isolation, which is why an uncommon word like "hota" passes
  through unconverted. See `bots/text_normalizer.py`'s docstring for why the lexicon is
  deliberately narrow rather than comprehensive.)

## Sample 3 (deliberately-excluded ambiguous words stay untouched)

- **input**: `please do the setup, this is the main network`
- **output**: `please do the setup, this is the main network` (unchanged -- see the
  module docstring for why "do"/"is"/"main"/"the" are excluded from the lexicon)
